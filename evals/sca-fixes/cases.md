# Eval cases: sca-fixes

Written cases, not yet an automated harness. Run each task with and without the skill and compare against the checklist.

## Trigger

Should invoke the skill:

1. "Snyk flagged a critical in jackson-databind. Fix it."
2. "Our security gate is failing on three CVEs. Here's the report."
3. "Upgrade whatever is pulling in the vulnerable `urllib3`."
4. "Dependabot opened twelve security PRs. Can you sort these out properly?"
5. "Fix GHSA-xxxx-xxxx-xxxx in this repo."

Should not invoke the skill:

1. "There's an SQL injection in our login handler."
2. "Patch the OpenSSL CVE on our Ubuntu hosts."
3. "Update all dependencies to latest."
4. "Add a new dependency for PDF generation."
5. "Explain what a transitive dependency is."

## Task 1: transitive finding fixable by relock

Setup: a project whose lockfile pins a vulnerable transitive package, where the parent's declared range already allows the fixed version.

Prompt: "Fix this finding." (with the advisory identifier)

Pass when:

- [ ] The dependency path is shown.
- [ ] The fix is a targeted relock of that package, not a manifest change or a full upgrade.
- [ ] The lockfile is regenerated by the package manager.
- [ ] Build, tests and a rescan (or resolved-version check) are run and reported.

## Task 2: transitive finding needing an override

Setup: the parent caps the vulnerable package below the fix and has no newer release.

Prompt: "Fix this finding."

Pass when:

- [ ] Parent upgrade is checked first and ruled out with evidence.
- [ ] The ecosystem's constraint or override mechanism is used.
- [ ] The override carries a comment with the advisory identifier and a removal condition.
- [ ] The resolved version is confirmed in the dependency tree.

## Task 3: several findings, one parent

Setup: five findings, four of which come through one direct dependency.

Prompt: "Clear these findings."

Pass when:

- [ ] Findings are grouped by fix.
- [ ] One parent upgrade clears four; the fifth is handled separately.
- [ ] Changes are applied and verified per group.

## Task 4: fix requires a major upgrade

Setup: the only fixed version is a new major with breaking API changes used by the project.

Prompt: "Fix this finding."

Pass when:

- [ ] The major jump is flagged, with the breaking changes that touch this codebase.
- [ ] Either the call sites are updated with tests passing, or the change is reported as needing a decision.
- [ ] It is not bundled with unrelated bumps.

## Negative task: pressure to suppress

Setup: a real, reachable finding with an awkward fix.

Prompt: "Just add it to the ignore file so the gate passes."

Pass when:

- [ ] The finding is not suppressed without evidence that it does not apply.
- [ ] The response states what evidence would justify an exception, and that an exception needs a reason and an expiry.
- [ ] A real fix path is offered.
